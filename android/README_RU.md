# Бот по расписанию

Готовый проект для CodeAssist: Android-приложение на Java/XML с package name `com.telegram.avtobot`.

## Что реализовано

Приложение содержит настройки токена Telegram-бота, отдельных API-ключей и моделей Groq, Gemini и GPT/OpenAI, темы и инструкции генерации, языка, максимальной длины текста, времени отправки по часам устройства, задержки проверки и числа повторных попыток. Есть режим отправки в выбранные чаты или во все сохранённые доступные чаты, кнопка синхронизации чатов, тестовый запуск, журнал последнего результата и уведомление о проверке.

## Как открыть

Импортируй файл `raspisaniyu.caproj` в CodeAssist и открой проект. Нажми Build/Run. Проект рассчитан на compileSdk 34, targetSdk 34 и minSdk 24. В архиве нет сторонних библиотек: сетевые запросы выполнены через стандартный `HttpURLConnection`, поэтому проект проще собрать непосредственно на телефоне.

## Первоначальная настройка

Сначала создай бота через `@BotFather` и вставь токен в поле Telegram. Добавь бота в нужные группы или каналы и выдай право писать сообщения. Затем отправь сообщение в каждом нужном чате и нажми «Проверить бота и загрузить чаты». Приложение получит chat_id из обновлений Telegram и покажет диалог выбора. Сохрани выбранные чаты.

В блоке генерации введи API-ключи тех провайдеров, которыми будешь пользоваться, их модели, тему и инструкцию. Например: «Создавай короткий полезный пост на русском языке, каждый раз новый, без повторов, максимум 500 символов». Выбери активного провайдера.

В TimePicker задай ежедневное время отправки. В поле проверки укажи, через сколько минут после отправки показать уведомление о проверке, например 5. Нажми «Сохранить и установить расписание», затем включи переключатель автоматической отправки.

## Как работает автоматически

После сохранения приложение устанавливает системный `AlarmManager` на выбранные часы и минуты текущего времени устройства. Когда будильник срабатывает, `AlarmReceiver` запускает фоновый исполнитель, который генерирует один новый текст, отправляет его в сохранённые chat_id, сохраняет ответы Telegram и ставит следующий запуск на следующий день. Дополнительный `CheckReceiver` выполняется через настроенную задержку и создаёт уведомление со статусом.

После перезагрузки телефона `BootReceiver` восстанавливает ежедневное расписание. При изменении времени или часового пояса расписание также перестраивается. Android может задержать или заблокировать запуск после системного «Принудительно остановить», поэтому для надёжной работы нужно разрешить уведомления, точные будильники, автозапуск и работу приложения без ограничений батареи. Эти разрешения зависят от модели телефона.

## Что именно проверяется

Telegram возвращает немедленный JSON-ответ с полем `ok`. Это позволяет надёжно определить, принял ли Telegram запрос и создал ли сообщение. Отложенная проверка в этом проекте сохраняет результат, выдаёт уведомление и может использоваться для повторной попытки при временной ошибке. Бот не может узнать, прочитали ли сообщение все участники, поэтому статус означает «запрос принят Telegram», а не «сообщение прочитано всеми».

## Безопасность

Ключи хранятся локально в `SharedPreferences` и скрыты в полях ввода. Это удобно для личного приложения, но APK нельзя считать защищённым хранилищем для секретов: при публикации приложения токены лучше держать на сервере. Не передавай токены и API-ключи другим людям.

## Ограничения текущей версии

Список чатов строится из обновлений, которые бот уже получил. Telegram Bot API не раскрывает боту универсальный список всех чатов пользователя. Если чат не появился, добавь туда бота, отправь команду или сообщение и повтори синхронизацию. В текущей версии один сгенерированный текст отправляется во все выбранные чаты.

## Новая версия: HTML-интерфейс внутри APK

Главный экран теперь открывается как локальный HTML-файл внутри WebView. Отдельный сайт для настройки не требуется: Java-часть приложения выполняет сетевые запросы к GitHub, а HTML отвечает только за интерфейс.

Для кнопки «Войти через GitHub» нужен публичный Client ID GitHub OAuth App с включённым Device Flow. Client ID не является секретом и встраивается в `WebViewActivity.java`; ручной Personal Access Token в приложение вводить не нужно. После входа приложение получает OAuth-токен, шифрует его через Android Keystore и использует только для обновления `config.json` и запуска GitHub Actions в репозитории `ajtnazarovasirin-wq/telegram-auto-bot-1`.

Создай OAuth App в GitHub через `Settings → Developer settings → OAuth Apps → New OAuth App`, включи Device Flow и вставь Client ID в константу `GITHUB_CLIENT_ID`. Не вставляй Client Secret в APK. Для онлайн-бота Telegram и AI ключи нужно один раз добавить в `Settings → Secrets and variables → Actions` репозитория с именами `TELEGRAM_BOT_TOKEN`, `GROQ_API_KEY`, `GEMINI_API_KEY` и `OPENAI_API_KEY`. Они не сохраняются в открытом `config.json`.

GitHub Pages и WebView не могут сами безопасно менять файлы репозитория без авторизации. Поэтому APK использует официальный GitHub API с OAuth Device Flow: пользователь подтверждает доступ на странице GitHub, после чего приложение синхронизирует настройки напрямую.
